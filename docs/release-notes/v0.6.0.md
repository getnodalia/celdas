*Celdas 0.6.0 completes macros: recording straight to Visual Basic, the code behind ThisWorkbook and each sheet, and the editor with help and errors in Spanish.*

## Español

### Novedades
- **Grabar una macro como Visual Basic.** El diálogo Grabar macro tiene ahora «Grabar como»: *Pasos* (una macro de Celdas, como hasta ahora) o *Visual Basic*. En este segundo caso, al detener la grabación queda un `Sub` en el proyecto VBA del libro, con el código que escribiría el grabador de Excel: `Range("B2").Value = "x"`, `Selection.Font.Bold = True`, `Range("A1:C3").Borders.LineStyle = xlContinuous`, `Rows("4:4").Insert`, ordenar, filtrar, copiar y pegar, hojas… Un libro sin proyecto recibe uno. Lo que no tiene equivalente en código queda como comentario, y el aviso dice cuántos comandos fueron.
- **Código de ThisWorkbook y de cada hoja.** Un proyecto nuevo empieza como el de Excel: `ThisWorkbook`, un módulo por hoja (`Sheet1`, `Sheet2`…) y `Module1`. Los módulos de hoja llevan el *nombre de código* de la hoja, que no cambia aunque la renombres o la muevas, y se guarda en el archivo. En una macro, `Sheet1.Range("A1")` alcanza esa hoja, `ThisWorkbook` el libro y `Me` el objeto detrás del módulo: un `Sub` de una hoja con `Me.Range("B2").Value = 1` escribe en esa hoja aunque haya otra activa. El explorador del editor muestra el nombre actual de la hoja junto al del módulo.
- **El editor, en español.** Las descripciones de las sugerencias, las firmas y las tarjetas al pasar el ratón, y los mensajes de error de sintaxis («se esperaba una expresión», «falta `End Sub`»…) salen en español cuando la interfaz está en español. El código y los nombres del modelo de objetos siguen en inglés, como en el editor de Excel.

### Límites
- **UserForms** (formularios): no se pueden abrir, diseñar ni ejecutar. Si un archivo trae alguno, se conserva intacto al guardar.
- **Eventos** (`Workbook_Open`, `Worksheet_Change`…): el código se puede escribir y ejecutar por su nombre, pero nada lo dispara por sí solo.
- El proyecto que Celdas crea en un libro nuevo no se ha probado con Excel; si Excel ofrece repararlo, el código se conserva.

## English

### What's new
- **Record a macro as Visual Basic.** The Record Macro dialog now has "Record as": *Steps* (a Celdas macro, as before) or *Visual Basic*. With the second, stopping the recording leaves a `Sub` in the workbook's VBA project, with the code Excel's recorder would write: `Range("B2").Value = "x"`, `Selection.Font.Bold = True`, `Range("A1:C3").Borders.LineStyle = xlContinuous`, `Rows("4:4").Insert`, sort, filter, copy and paste, sheets… A workbook without a project gets one. What has no code equivalent stays as a comment, and the notice says how many commands that was.
- **The code behind ThisWorkbook and each sheet.** A new project starts like an Excel one: `ThisWorkbook`, a module per sheet (`Sheet1`, `Sheet2`…) and `Module1`. A sheet's module carries the sheet's *code name*, which does not change when you rename or move the sheet and is saved in the file. In a macro, `Sheet1.Range("A1")` reaches that sheet, `ThisWorkbook` the workbook and `Me` the object behind the module: a `Sub` in a sheet that says `Me.Range("B2").Value = 1` writes to that sheet whichever one is active. The editor's explorer shows the sheet's current name beside the module's.
- **The editor, in Spanish.** The descriptions of suggestions, signatures and hover cards, and the syntax error messages ("se esperaba una expresión", "falta `End Sub`"…) appear in Spanish when the interface is Spanish. The code and the names of the object model stay in English, as in Excel's editor.

### Limits
- **UserForms** cannot be opened, designed or run. A form that a file brings is kept untouched when you save.
- **Events** (`Workbook_Open`, `Worksheet_Change`…): the code can be written and run by name, but nothing starts it by itself.
- The project Celdas creates in a new workbook has not been tried with Excel; if Excel offers to repair it, the code is kept.
